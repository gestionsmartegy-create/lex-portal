# ADR 0011 — Durcissement J3.1 (bonnes pratiques 2026)

- **Statut** : accepté (2026-10-02)
- **Contexte** : revue des bonnes pratiques 2026 de J1 à J3, demandée par le responsable du projet. Aucune faille n'a été trouvée, mais plusieurs manques. J3.1 traite ceux qui ne demandent **aucune décision du cabinet**. Les autres sont inscrits dans `docs/open-questions.md`.

## Décision

| # | Sujet | Décision |
|---|---|---|
| 1 | Alertes de sécurité | **Envoyées par Supabase Auth lui-même** (`[auth.email.notification.*]`) : mot de passe, e-mail, ajout ou retrait d'un facteur MFA, identité liée ou déliée. Elles partent donc aussi lors d'un appel direct à l'API Auth. Gabarits `supabase/templates/*_notification.html` : **bilingues EN puis FR** dans un seul e-mail (Supabase n'a qu'un gabarit par événement), **sans lien ni donnée de dossier**, avec la consigne « contactez le cabinet par téléphone ». **Exception documentée** à la règle « aucun texte en dur » : ces gabarits sont du HTML statique servi par GoTrue, hors de l'application. Test d'intégration : un changement de mot de passe produit l'alerte dans Mailpit. |
| 2 | Pages d'erreur | `app/[locale]/error.tsx` : textes traduits, bouton « Réessayer », seule l'empreinte `digest` est affichée, jamais le message technique. `app/global-error.tsx` : rendu minimal bilingue, lu directement dans `messages/*.json`, car next-intl n'est plus disponible à ce niveau. |
| 3 | Rapports CSP | Directives `report-to csp` et `report-uri`, plus l'en-tête `Reporting-Endpoints` (URL absolue). Point de collecte `POST /api/security/csp-report` : types de contenu acceptés limités, 16 Ko maximum, limite de débit par IP (60/min), validation Zod. Le log est structuré **sans URL complète** : directive, origine bloquée, chemin de page sans requête ni fragment. La réponse est toujours 204. |
| 4 | Trusted Types | `require-trusted-types-for 'script'` en **observation seule** (`Content-Security-Policy-Report-Only`). Les e2e ne montrent aucune violation sur les pages publiques ni sur le portail. On ne passe pas encore en blocage : les pages `/admin` ne peuvent pas être testées en build de production avant la configuration de Microsoft. La bascule est prévue en J6, une fois tous les écrans couverts par les e2e et les rapports vides. |
| 5 | En-têtes | `Cross-Origin-Resource-Policy: same-origin` ajouté. `/.well-known/*` reçoit la CSP stricte des API et n'est pas routé par la langue. |
| 6 | security.txt | `/.well-known/security.txt` (RFC 9116). Contact : **admin@lexcanadalaw.com**, fourni par le responsable le 2026-10-02 (`lib/security-txt.ts`). `Expires` est recalculé à J+180, puis viennent `Preferred-Languages: en, fr` et `Canonical`. |
| 7 | CI | `app` : `pnpm audit --prod --audit-level=high`, bloquant. `secrets` devient « Sécurité (secrets, analyse de code) » : **Semgrep CE** épinglé (publié depuis plus de 7 jours), exécuté dans le runner sans envoi du code (`--metrics=off`), règles `p/typescript`, `p/react`, `p/nextjs`, `p/secrets`, bloquant sur les erreurs. **CodeQL n'est pas possible** : il exige GitHub Advanced Security pour un dépôt privé sur un compte gratuit (ADR 0008). Les noms des 3 contrôles d'AGENTS.md §10 sont conservés. |
| 8 | Dépendances | `minimumReleaseAge: 1440` (1 jour) rendu **explicite** dans `pnpm-workspace.yaml`. C'est la valeur de pnpm 11 ; 7 jours rejetteraient le lockfile actuel. Les mises à jour courantes passent par Dependabot, avec un délai de 7 jours (ADR 0009). |
| 9 | e2e avancés de J6 | Playwright + axe (`pnpm test:e2e`). Le **build de production** (`output: "standalone"`, servi par `scripts/serve-standalone.mts`) tourne contre Supabase local, en desktop et à 375 px. Scénarios : connexion puis enrôlement TOTP réel, portail (RLS : 1 dossier), déconnexion ; message neutre ; renvoi du personnel vers Microsoft ; redirection ouverte refusée ; **aucune violation CSP dans la console** ; **axe sans violation grave ni critique (WCAG 2.2 AA)** ; en-têtes ; security.txt ; point de rapport CSP. Une IP simulée par test (`x-forwarded-for`) isole les limites de débit sans les désactiver. Ces tests tournent en CI dans le job `database`. |
| 10 | Accessibilité (trouvé par axe) | `gold-ink` passe de `#8A6D1A` à **`#7F6416`** : l'ancienne valeur donnait 4,49:1 sur le fond `surface` (#F4F5F7), sous le seuil AA de 4,5:1. La nouvelle donne 5,6:1 sur blanc, 5,15:1 sur `surface` et 4,65:1 sur `gold-pale`. Le pied de page du panneau marine passe de `white/40` à `white/60`. Les liens texte isolés ont une zone cliquable d'au moins 24 px (WCAG 2.2, critère 2.5.8). **À valider par le responsable** : la nuance diffère de la couleur choisie en J1. |

## Conséquences
- Toute nouvelle page est couverte par les e2e (axe et absence de violation CSP) avant d'être considérée comme terminée.
- Les rapports CSP arrivent dans les logs du serveur. Leur exploitation (alertes) dépend de l'outil de surveillance, qui reste à choisir (open-questions).
- En production, `TRUSTED_PROXY_HOPS` doit correspondre à l'hébergeur (ADR 0010, M2). Sinon, un client peut choisir son IP et contourner les limites par IP.
